# Блог до 23 октября: заливка и настройка

В архиве всё: 20 статей, автопубликация по расписанию, автоотправка в Яндекс, вёрстка блога. Файлы, которые уже есть в репозитории, перезапишутся такими же — это безопасно.

Пять шагов, около 15 минут. После этого блог работает сам до 23 октября.

---

## Шаг 1. Залить файлы

1. Открыть **github.com/baikaltarget/https-btctour.ru-**
2. **Add file** (справа, рядом с зелёной кнопкой Code) → **Upload files**
3. Распаковать архив у себя на компьютере
4. Перетащить в окно браузера папки `content`, `lib`, `app`, `scripts`, `public` и файлы `vercel.json`, `CHANGELOG.md`
5. Папку **`.github` браузер перетащить не даст** — она начинается с точки. Это шаг 3
6. Внизу — зелёная **Commit changes**

⚠️ В папке `public` лежит файл с длинным именем из букв и цифр — это ключ для Яндекса, он должен попасть на сайт. Не удаляйте и не переименовывайте.

---

## Шаг 2. Удалить старую статью про Ольхон

Сейчас на сайте две похожие статьи об Ольхоне: новая и старая сдвоенная. Они мешают друг другу в поиске.

1. Открыть **github.com/baikaltarget/https-btctour.ru-/blob/main/content/blog/olkhon-zimoy-i-letom.md**
2. Справа сверху значок **корзины** (Delete this file)
3. Внизу **Commit changes**

Редирект со старого адреса на новый уже стоит. Проверить: `btctour.ru/blog/olkhon-zimoy-i-letom/` должно перебросить на `/blog/olkhon-zimoy/`.

---

## Шаг 3. Создать файл расписания

1. В репозитории: **Add file** → **Create new file**
2. В поле имени вписать ровно это:

```
.github/workflows/publish.yml
```

   Как напечатаете слэш, GitHub сам сделает папки
3. В большое поле ниже вставить содержимое файла `publish.yml` из архива (папка `.github/workflows/`) — открыть его можно Блокнотом
4. Внизу **Commit changes** → в окошке ещё раз **Commit changes**

Проверить: в репозитории появилась вкладка **Actions**, в ней слева «Публикация по расписанию».

---

## Шаг 4. Ссылка на пересборку в Vercel

1. **vercel.com** → войти → выбрать проект сайта
2. Сверху **Settings**
3. В меню слева **Git**
4. Прокрутить до раздела **Deploy Hooks**
5. **Hook Name:** `blog-schedule`, **Git Branch Name:** `main`
6. **Create Hook**
7. Появится длинная ссылка — нажать **Copy** рядом с ней

Ссылка работает как кнопка «пересобрать сайт». В чаты её не выкладывайте.

---

## Шаг 5. Секрет в GitHub

1. Репозиторий → сверху **Settings** (настройки репозитория, не профиля)
2. Слева **Secrets and variables** → **Actions**
3. Зелёная **New repository secret**
4. **Name:** `VERCEL_DEPLOY_HOOK` — ровно так, заглавными
5. **Secret:** вставить ссылку из шага 4
6. **Add secret**

---

## Проверка

1. GitHub → **Actions** → слева **Публикация по расписанию** → справа **Run workflow** → ещё раз **Run workflow**
2. Задание идёт около трёх минут (внутри ожидание сборки) и заканчивается зелёной галочкой
3. Нажать на задание → шаг «Сообщить Яндексу о новых статьях»: там список отправленных адресов и ответ поисковика
4. Vercel → **Deployments**: сверху новая сборка

Красная галочка — откройте задание и прочитайте сообщение. «Секрет VERCEL_DEPLOY_HOOK не задан» означает, что на шаге 5 имя сохранилось с ошибкой.

## Если передумали с датой

- **Опубликовать раньше:** открыть файл статьи на GitHub → карандаш → поменять `date:` на сегодняшнюю → Commit. Выйдет сразу
- **Сдвинуть позже:** так же, дату побольше. Только для статей, которые ещё не публиковались: если спрятать проиндексированную страницу, поисковик получит 404
- **Пересобрать вручную:** Actions → Публикация по расписанию → Run workflow
